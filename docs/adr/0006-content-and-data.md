# 0006: Write-ups in git, run data in Supabase

**Context.** Write-ups are edited by hand and reviewed like code. Run data is
generated by machines, can be large, and must never be hand-edited.

**Decision.**

- Write-ups: MDX in `content/<collection>/`, front matter validated with zod at build and in CI.
- Run data: JSONL on the lab machine is the source of truth. `lab sync` publishes validated logs to Supabase (`runs`, `events`), idempotently. Events are append-only in the database too.
- A write-up references runs by `run_id`. Numbers on the site are computed from events, never typed into front matter.
- Publishing is explicit: a run is visible only after it is marked published in /admin.
- Media (video, images) goes to Supabase Storage, referenced from write-ups. Not in git.

**Consequences.** Text and numbers can't drift apart; a typo fix doesn't touch data;
a data correction is a new run, which is itself honest history.
